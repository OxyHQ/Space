# Chat API (transitional)

Station still carries a local chat runtime while Hub AI is moved to
Alia -> Oxy -> Kaana. This page documents only the behavior currently emitted
by the Station source; it does not describe the destination architecture.

## Endpoints and authentication

```text
POST https://api.station.oxy.so/v1/chat/completions
POST https://api.station.oxy.so/clarity/search
```

`/v1/chat/completions` requires an Oxy session JWT or a separately provisioned
internal service credential in `Authorization: Bearer <token>`.
`/clarity/search` mounts the same handler with optional Oxy authentication for
the existing Station client.

Station has no mounted developer API-key management route. Provider keys and
provider identifiers are not client credentials.

## Request

The handler accepts an OpenAI-style `messages` array. `input` is accepted as an
alias. The model defaults to Station's default virtual model when omitted.

```json
{
  "model": "clarity-v1",
  "messages": [
    { "role": "user", "content": "Summarise this workspace" }
  ],
  "stream": true,
  "stream_options": { "include_usage": true }
}
```

The source also reads these optional fields:

- `conversationId`
- `thinkingMode`
- `agentMode`
- `tools`
- `temperature`
- `max_tokens`
- `stream_options.include_usage`

Unknown fields should not be treated as supported features.

## Response modes

With `stream: false` or no `stream` field, the route returns an
OpenAI-compatible `chat.completion` JSON response.

With `stream: true`, it sends Server-Sent Events. Frames without an `event:`
line are OpenAI-compatible `chat.completion.chunk` payloads. The final frame is
`data: [DONE]`.

The only named events emitted by the current handler are:

| Event | Payload |
| --- | --- |
| `oxystation.reasoning` | `{ eventVersion: 1, content }` |
| `oxystation.tool_result` | `{ eventVersion: 1, tool_call_id, name, output }` |
| `oxystation.agent` | `{ eventVersion: 1, agentId, agentName, agentHandle, agentAvatar, content }` |
| `oxystation.title` | `{ eventVersion: 1, title, conversationId }` |

Clients must ignore named events they do not understand. This runtime does not
emit the former `clarity.*` research, approval, trigger or model-switch event
contract.

## Conversation persistence

When `conversationId` and an authenticated user are present, the runtime can
persist the result and emit a title update. Conversation CRUD is separately
available under `/conversations` and remains user-scoped.

## Errors

Before streaming begins, validation and authentication failures use the normal
HTTP status and an OpenAI-shaped error body. After SSE headers have been sent,
the handler emits an OpenAI-shaped error frame, then `data: [DONE]`, and closes
the stream.
